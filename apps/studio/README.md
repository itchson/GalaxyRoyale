# Mission Control

The production dashboard is local and independent of the released game. Start the API with `node apps/studio/server.mjs` and the frontend with `npx vite --config apps/studio/vite.config.ts` (the root development script starts both). UI: `http://127.0.0.1:4175`; API: `http://127.0.0.1:4174`.

Only the API writes `production/project.json`. It serializes updates, preserves a previous-document `.backup`, atomically replaces the JSON snapshot, and emits a real SSE update after persistence. Do not edit this file concurrently with the API. Task Active means recorded work state, not live agent presence. Feedback is queued for an active Codex session to read; the dashboard cannot wake sessions.

## Agent CLI

`node scripts/studio-cli.mjs snapshot`

`node scripts/studio-cli.mjs task update studio --file work/studio-update.json`

Example UTF-8 update payload:

```json
{
  "author": "Production specialist",
  "source": "Actual implementation and validation in the current Codex session",
  "expectedRevision": 1,
  "patch": {
    "status": "review",
    "evidence": [{ "label": "Studio tests", "kind": "test", "path": "work/studio-tests.log" }]
  }
}
```

Create commands: `task`, `review`, `decision`, `build`, or `feedback`, followed by `create --file <payload.json>`. A task creation uses `{author,source,task:{title,...}}`. Other records use `{author,source,record:{title,body,...}}`. Reviews include `participants` and optional `taskIds`. Decisions include `status` (`proposed`, `accepted`, `rejected`, `superseded`). Builds include `revision`, `checks:[{name,result,details?}]`, optional `url`, `knownIssues` and `evidence`. Check results are `pass`, `fail`, or `not_run`; report device coverage explicitly. Feedback updates use `feedback update <id> --file <payload.json>` with `expectedRevision`, `status` (`queued`, `acknowledged`, `resolved`) and `response`.

Task patches require the latest task `expectedRevision`; stale writes return 409. Completion requires all criteria met, completed dependencies and evidence. Artifact paths must reference existing files within `work/`, `artifacts/`, `dist/`, or `apps/game/dist/`. Files resolving outside these directories are rejected. Evidence notes record assertions and outcomes; the service does not itself rerun tests or verify an asserted pass.

Test: `node --test apps/studio/test/*.test.mjs`. Build: `npm run build:studio`.

## Recorded agent runs

`POST /api/runs` and `node scripts/studio-cli.mjs run create --file <payload.json>` append an observation to `runRecords` and the activity log. Run records cannot be edited or deleted by the API. Payload: `{author,source,record:{agentId,agentLabel,state,observedAt,taskIds,summary,evidence}}`. Use a stable space-free agent identity, UTC ISO `observedAt`, existing task IDs and evidence (a source-backed observation note or an existing artifact). States: `running`, `completed`, `interrupted`, `failed`, `blocked`. Future timestamps are rejected, with 30 seconds allowed for clock skew. The service adds `createdAt`; missing run history in older snapshots loads as an empty list.

The board shows the last appended observation for each agent; Activity shows the complete history. A completed run scope does not complete the linked tasks. Recording a running state does not assert that the agent remains connected, and there is no session polling or wakeup mechanism. Observations must come from actual session exchanges or outputs; record the current observation time when a precise earlier time is unavailable rather than inventing a start or completion time.
