# Runtime integration contracts

- PixelInstance is 16 bytes: local.xy, little-endian RGBA, transform index. GpuTransform is 32 bytes: position.xy, basis_x.xy, basis_y.xy, light response, emission. Up to 128 transforms share a 4,096-byte table. Materials clamp finite values to 0..1.
- PixelBody separates occupancy from color. Local swept hits test surviving cells; damage returns removed centers/colors. Exact affine composition preserves shear; FrameBuilder reuses capacity.
- Input contains optional joystick/new world destination, transient world-space aim and fire. Destination persists in Rust; aim is resubmitted each frame while desktop right fire is held and recomputed from the latest presented unshaken camera/world viewport. Valid active aim overrides facing through the existing 720°/second turn; course velocity/braking and aim-active keyboard thrust remain independent. Shots use the actual nose and quarter ship-velocity inheritance, including during turns. Release/cancellation/disabled controls clear aim. Mobile fire supplies no aim and keeps heading-based steering/fire. No aim field is saved.
- Game provides tick, render_into, HUD/events/profile, purchase, craft_ability, upgrade_ability, equip_ability, interact_site, density, pause, cancel_course and explicit QA scenes. cancel_course clears only the persistent destination; the browser boundary also clears a queued one. HUD ship_stats supplies actual speed and current effective top_speed/acceleration/primary_damage/fire_rate/hull_regen/shield_regen. Regen rates retain their actual no-hit delays. At most eight interpolated world lights reach the renderer.
- Launched game menus gate controls while simulation continues. Escape toggles live ship telemetry, Settings replaces that content, and title/restart are explicit abandonment boundaries. Title Quit saves and flushes before requesting browser close, with a usable ordinary-tab fallback. Console/dialogue, death, hidden tab, renderer loss, portrait touch and critical save preparation are separate lifecycle gates; menu visibility is not a simulation gate. Repeated state reconciliation must not reset the fixed-step accumulator.
- Schema 4 retains revision/seed, currency, kill/boss/pity/queues, discoveries/quests/relics and campaign results. Campaign stores ship_xp[10], abilities[17] (blueprint/rank), loadouts[10] (hardware[6], slots[3]), five-tier cargo_materials/stored_materials and last_run with materials_lost[5]. Slot values are an owned compatible catalog index or explicit null. Cargo totals at most 16; each material counter is u32. Optional Rust values cross the shared WASM serializer as explicit null. Live entities/drops/damage are transient.
- Profile.ranks/unlocked are compatibility mirrors, not a second inventory: ranks 0..5 mirror the selected hull's stored hardware; ranks 6..8 and unlocked mirror ordinary boss ability ranks/blueprints. Each hull owns its hardware and XP. Ability ownership/rank is shared, but only an equipped compatible slot applies its effect. Normal effective ability/hardware ranks are capped by active ship level; HUD reports stored rank and effective_rank separately. Three equipped Sovereign royal bundles and its enhanced chassis/hardware are explicit rank-five exceptions and do not invent XP.
- Storage accepts schemas 1..4, validates bounds/compatibility/mirrors, compares revisions and retains a previous snapshot. V1..3 migration preserves recorded currency/XP/counters and converts legacy scalar crafting cargo plus storage once to Tier 1 stash. Legacy hardware moves only to the selected owned hull; learned family/native champion effects receive explicit compatible loadouts. Schema 4 validation/save/export retain live cargo; Game::new discards that cargo on a fresh run without banking it. Physical Haven arrival banks cargo, while death/Title/restart abandonment discards it. Courier mission packets are separate.
- IndexedDB database version 2 preserves the existing profile store and records while upgrading version 1 in place. An older open connection blocks that upgrade; the shell asks the player to close other game tabs and waits without creating a fresh profile. A versionchange closes an obsolete connection and rejects queued/new save or import writes until reload. VersionError requests a newer game build and refuses an in-memory fresh run, preventing an older cached build from overwriting schema 4 progression.
- The five-generation content extension adds boss_generations[family][generation0..4]. Earlier missing/all-zero family rows preserve aggregate boss_kills as generation1. Nonzero rows obey previous-tier two-defeat promotion; boss_kills remains the u32-saturated row sum. Base pending flags reserve generation1 only. Same-schema normalization rewrites current/previous snapshots transactionally without changing reward credit or revision.
- Ordinary BossHud carries family, generation1..5, bounded phase text and telegraph state. Champion/league duels use generation0. Family progress exposes defeated and queued counts separately from the live encounter, so a completed kill cannot be confused with a pending/retried fight.
- Galaxy batches HUD/events/changed profile/counts/CPU timings across WASM. Browser APIs manage viewport/UI/insets/touch/settings/recovery.
- UI groups have viewport-relative parents; nodes have local rectangles/text/font/value/interaction/clips. Semantic DOM supplies layout/input/accessibility; Rust renders RoyaleMono and real pixel bodies after world layers. Console/dialogue share this contract.
- WebGPU/WebGL2 share gameplay. Initialization uses a fresh fallback canvas; async prepare_renderer_recovery holds no Galaxy borrow, and synchronous install_recovery consumes the candidate while retaining Game. Actual WebGL lost/restored lifecycle gates rebuilding. Permanent recovery failure latches until an explicit retry.
- Studio mutations use its localhost service: atomic writes, expected revisions, append-only records and criteria/evidence requirements. PWA caching excludes Studio/API.

Circular arena wrapping is opt-in. Future authoritative multiplayer needs camera/history/destination rebasing and split collision seams. See UNIVERSE_TOPOLOGY.md and ROADMAP.md.

## Dock inventory and UI boundary

The stable ability registry has 17 entries: starters 0..2, family boss blueprints 3..5, champion blueprints 6..13 and Sovereign royal bundles 14..16. Category 0/1/2 is offense/defense/passive; champion ship construction currency is a separate classification. Starter/boss abilities are universal, champion abilities use authored hull-family masks (Scout is Dart; Sovereign accepts normal abilities), and royal bundles are Sovereign-only. Do not infer categories from ship names or champion construction currencies.

`purchase(hardwareId)`, `craft_ability(abilityId)`, `upgrade_ability(abilityId)` and `equip_ability(category, abilityId | null)` are atomic home-only operations. Craft acquires ownership without automatic equip. Equip swaps one category slot and retains displaced owned inventory. HUD `can_purchase/can_craft/can_upgrade/can_equip/can_select` and operation-specific reason strings use the same checks as these APIs, including real banked tiers and ship-level/compatibility gates. The shell displays these flags/recipes rather than duplicating affordability rules.

The dedicated Forge helper preserves category/focus/scroll on repaint, resets on fresh open or hull change, and has only a contextual Back control. Hangar receives full per-hull XP/recipe metadata. Root callbacks apply the real mutation, obtain fresh HUD, save the actual profile snapshot, then repaint. A mutation-success message is distinct from committed persistence; save-pending/failure indicators remain authoritative. See CAMPAIGN.md for recipes and migration details. Native/browser/human/physical acceptance must be recorded separately for each actual build.

## Desktop navigation and discovered space

InputFrame.thrust is a transient held-left unshaken world cursor. Valid joystick input takes precedence; otherwise a valid held cursor applies full forward thrust and steers smoothly. Right-fire aim overrides heading. A near-center held cursor retains heading rather than cutting throttle. Release restores the persistent destination's arrival braking. Reset/cancellation consumes held state and clears the Rust course; ordinary pointer release retains its route.

The separate universe_map() WASM call regenerates only canonical Profile.discoveries from the seed, plus live ship position/heading and Haven's real radii. It is requested on map entry and approximately once per second while visible, keeping up to 256 discoveries out of every-frame HUD traffic. Site status and quest progress come from the same gameplay records as interaction. Unknown sites and invented biome boundaries are not exposed. Set Course uses ordinary flight navigation; map interaction never teleports or awards progress.

Remote resource annuli use canonical site-centered radii outside the sanctuary. Immutable asteroid birth metadata chooses the reward tier before drift or destruction. Haven's 700–1,400 tutorial annulus retains priority, Tier 1 rewards and no asteroid XP. Remote belt tiers follow the existing outward danger thresholds and provide higher-tier materials; recommendation labels do not invent a separate ability-rank gate.

Belt rocks own seeded orbital center/radius/spin/speed metadata. A capped restoring acceleration guides tangential motion while shot and contact impulses remain physical. Every asteroid, including outer-space rocks, collides with Haven and canonical sanctuary circles expanded by its conservative body radius. Swept earliest-contact reflection prevents crossing a shield between ticks; post-contact correction keeps pair-separation impulses outside it. The boundary cannot damage a rock or award XP, points or materials. These circles are the same protection radii reported by the map.

Normal WASM output contains one complete content-addressed four-file binding set per backend and a validated builds.json. Vite embeds the exact glue URLs; each glue's relative binary stays in that same hashed directory. The service worker reads navigation and assets from its own build cache, preserving a coherent offline shell. New hashed paths bypass historical stable-path caches. A previous valid manifest is retained when either staged backend is incomplete. Generated cleanup is restricted to verified owned directories; unknown entries and filesystem links are rejected.

## Native flight presentation and adaptive audio

FlightStatusLayout is a shared, allocation-free native visual layout. The normal browser painter and boss reservations use its22logical-cell strip,7cell context row and projected hull/shield tracks. Projection uses the actual interpolated player focus, unshaken camera and eased world zoom. Constant logical-sized UI remains on its separate crisp target. Bars that cannot clear the safe area, toolbar, touch pads or actual semantic hits are omitted; H/S summaries remain in the strip. Legacy HUD wrappers are compatibility helpers rather than the normal runtime painter.

flight_status_bounds() and flight_status_text_bounds() export small logical rectangles; the shell scales them to physical CSS pixels without rounding. Actual context hits use max(44physical pixels,22logical cells), center on the glyph row and clamp to safe vertical bounds. A hit that overlaps measured movement/fire/toolbar rectangles is hidden without deleting the fitting toast slot. Native status-hit nodes reserve actual clipped pointer bounds separately from seven-cell status-text glyphs. Transient messages take precedence over contact hits. Save text remains concise; tooltip and Savepage retain the full persistent-storage reason.

HUD.audio is transient authoritative presentation state, never a saved gameplay counter: area, biome, actual pursuing hostiles/combat, actual champion, boss presence, normalized positive hull/speed/throttle and surviving exhaust ports. The frame submits it once after each step. Music uses authored common-harmony themes with bounded crossfades, pursuit-driven percussion and a low-hull alarm layer. Actual effect/shot/impact events select distinct synthesized cues; engine pitch and level follow actual throttle/speed. AudioContext creation requires the launch gesture. Bounded scheduled/continuous voices use separate music/effects buses, smooth gain envelopes and an output limiter; suspension releases voices and guards asynchronous resume. Recorded Web Audio tests verify graph/lifecycle/scheduling, not audibility or browser DSP. Published QA diagnostics are readonly snapshots of the actual context/mix/voice state.
