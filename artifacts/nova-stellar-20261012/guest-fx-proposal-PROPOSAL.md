# Independent guest transient-presentation proposal

Reviewed source: `ab71442b9540c3f33c61a418d445323a1b9ccc1e`. This proposal was completed before reading the running Spark audit's result. It is source inspection/design only: no implementation, native test, build, listener or browser action.

## Actual boundaries and missing data

`GameEvent` is `{kind,x,y,intensity}` without sequence, lifetime, session or participant (`game_core/lib.rs:284`). `event()` creates some lights before admitting at most 128 cue records; `take_events()` drains that one queue (`:757`, `:999`). Draining it for network publication would compete with the host shell and other guests. The current main handler also maps every `death` cue to local death UI (`apps/game/src/main.ts:1706`), so a remote pilot's cue must never enter that generic route unchecked.

Host light storage is bounded to 32. Birth validates finite inputs, clamps radius/color/intensity, and records both remaining and initial life (`lib.rs:885`). Each authoritative solo/co-op tick reduces life and removes dead entries (`lib.rs:1209`, `co_op.rs:619`). Native selection considers only four recent visible effects, two nearby projectiles, the host engine and a beacon, with a final eight-source bound (`lib.rs:783`). That selected host-view array is unsuitable for another camera.

Particles have actual birth anchor, local/previous-local motion, velocity/acceleration, remaining/initial life, RGBA, size, seed and style (`lib.rs:432`). `styled_particle()` admits only finite positive inputs, life <=3 seconds, velocity <=1500, and the existing 1,100-particle pool (550 with reduced cosmetics; stress mode is outside this co-op scope) (`:2749`). Admission determines the cosmetic seed. Authoritative ticks integrate and retire them (`:2889`); extraction preserves fractional size and world anchor, handles native hard/soft material and visibility, and applies local reduced detail (`:2932`). Host projectile-trail births themselves select eight host-visible projectiles (`:2828`), so even copying all current host particles would not prove every guest's exhaust/trail parity.

Ordinary Echo and Nova already emit real host effects (`co_op.rs:727`, `:983`). Nova has an explicit .45-second light, 36 deterministic .4-second debris rays and the existing `ability-nova` event/.32-second light. Damage/reflection/cooldown and the owner attribution are authoritative gameplay; they must never be replayed by a guest to recreate a visual. Echo's eight-particle `burst` consumes actual host random values and admission state; its birth data cannot be reconstructed faithfully from an `ability-echo` cue alone.

The retained host publication currently captures pilots/projectiles and real entity/body data only (`co_op.rs:175`, `co_op_publish.rs:122`). Replica retains no transient payload; its lights are two projectile sources plus dock (`co_op_replica.rs:180`), HUD particles are zero (`:479`), and guest `Galaxy.step()` returns no cues (`game_web/browser.rs:665`). Guest pose interpolation age resets after every successful commit (`co_op_replica_bridge.rs:113`); it is not an effect lifetime clock. Publication acquisition/commit already guards session, revision, epochs, counts and complete bodies. Body transfer waits for acknowledgements and is rate-limited, so a short effect can expire before a coherent capture arrives (`coop/controller.ts:837`).

## Smallest recommended implementation

Start with **ordinary Nova presentation only**, preserving the current authoritative attack unchanged. Introduce a compact, non-destructive session-owned presentation journal. Record a checked monotonic FX sequence, host tick, exact emitter participant/epoch and the real admitted ray prefix count (0..36); retain the actual remaining lifetime at capture. Record only after the real trigger, never from incoming input, health deltas or inferred projectile patterns. Use a pure native Nova appearance/birth helper shared by the host emitter and replica; guest replay must have no access to damage, bullet reflection, Actor, RNG progression or Profile. Secondary explosion/debris caused by the attack remain explicitly outside this first increment.

Capture those records with the existing coherent acquisition and participant roster, using an additive omitted-when-empty field or a small bounded FX page. Do not enlarge a maximum-size snapshot blindly: the current 8-pilot/180-projectile fixture is already approximately 45 KB against the 64 KiB frame limit. Suggested journal/page ceilings are 128 records and 32 records/page, subject to actual serializer size tests and the current shared transport rate. No per-frame full 1,100-particle snapshot, new reliable backlog, or independent gameplay tick is needed for this increment.

Guest native presentation owns its bounded transient cache, using the same 1,100-particle/32-light maxima and native extraction/material path. Only committed records can emit. Validate finite world positions, numeric bounds, allowed kind, exact session and emitter membership/epoch; a queued record for another epoch cannot attach to a replacement pilot. A native FX sequence is separate from the existing wrapping cosmetic seed and from acquisition number. Repeated records across acquisitions are deduplicated; advance the accepted high-water mark only after the whole pending acquisition validates and commits. Any journal truncation must expose a gap/drop count; it must not fabricate missed activations.

Age from authoritative captured tick/remaining lifetime plus native elapsed time since receipt, including time spent assembling bodies. Never restart TTL at body commit, reuse capped pose alpha as age, extend an expired effect upon reacquisition, or rerun an effect after a duplicate packet. Drop already expired records rather than produce a late full burst. Receiver elapsed time accounts for observable assembly delay, not unknowable one-way network latency; this design does not promise time-matched host/guest pixels. A paused/hidden/stalled receiver must expire pending presentation on resumption rather than accumulate catch-up bursts.

Membership changes invalidate pending records against the newly committed roster; participant-attached cache entries for retired epochs clear. World-anchored, already emitted rays can finish their bounded lifetime without becoming a new pilot's effect. Session end/new session/disposal clears journal, pending cache and cue dedup; failed acquisitions retain the prior valid scene/cache without emitting pending FX. Boxed solo restoration remains exact. Guest audio delivery, if added, is a bounded safe cue whitelist (initially `ability-nova`), never remote death/mission/save actions; it still obeys the shell's visible/running audio policy.

## Required acceptance before claiming the slice

- Real Nova trigger -> actual host ray admission -> serializer -> transactional native replica -> expected hard-cell packet, fractional camera/zoom and correct light expiry; test reduced detail separately from host pool admission.
- Duplicate/reordered acquisition, failed body commit, stale session, old emitter epoch, same-ID rejoin, journal gap, queued end/dispose and overflow do not replay cues or effects.
- Partial host ray admission at the real pool cap is preserved; guest overflow is bounded and reported as a presentation omission. No gameplay/body/projectile/reward cap increases.
- Timer boundary and long body transfer tests prove no restart after expiration; frozen source fixtures identify configured history honestly. Actual encoded maximum FX page/frame sizes and mixed packet costs are measured.
- Original solo effects/profile restoration and current authority collision tests remain unchanged. A real guest browser sees the effect using both native backends before rendered acceptance; audio and moving/network-delay parity stay distinct gates.

This deliberately does not implement general replicated random debris, exhaust, trails, all abilities, local death UX or shared rewards. Those need actual native birth/state metadata and targeted ownership/lifetime policy, not a generic event-to-particle imitation. The Spark comparison will be a separate amendment so this independent source-backed proposal remains unchanged.
