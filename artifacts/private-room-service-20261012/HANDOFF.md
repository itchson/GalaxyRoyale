## Coordinated exact contract

Production room codes use crypto `randomBytes(4)`, collision checked against all current/retired reservations, maximum 32 attempts. Display is `#A7C2-9F34`; raw input at most64 code units; strip ASCII TAB–CR/space and hyphens plus one optional leading hash, then require exactly8 case-insensitive hex digits. Codes are lookup identifiers, not encrypted bearer credentials. The existing `invite` response/request key carries the canonical code. Matching rebuilt clients required; unchanged gameplay protocol does not mean old encrypted-envelope clients remain compatible.

New host-only endpoints: `/v1/code` body `{}` rotates within the same room; `/v1/joining` body `{locked:boolean}` changes policy; `/v1/approval` body `{peer:32hex,accept:boolean}` resolves one pending request. Administration requires the separate existing64-hex host token. A30/minute authenticated admin bucket consumes attempts before request-body parsing, with unauthorized guests denied before that bucket. Whole-session `/v1/replace` retains its previous operation and owner/global create-rate contract.

Every session view adds required `joining_locked:boolean`, `room_revision:integer` and `room_code:string|null`. Only a host-authenticated view contains the current canonical code; every pending/active/retained guest view contains null. Codes/tokens never appear in service diagnostics; diagnostics now also provide reserved code count. The revision starts0, advances rotation and actual lock-state changes, and stays unchanged for no-op unlocked updates. Host views always carry the complete revision/code/lock tuple, so adopting newest revision cannot lose a rotation when a newer lock response arrives first.

Join returns201 `{session,participant:{id,role:'guest',status:'pending',token},cursor}` and reserves a seat without enabling RTC. Host event `join-request` contains `seq,type,peer:{id,role:'guest',status:'pending'},expires_at,room_revision` (birth revision). A request expires after20 seconds even with heartbeats. Accepted approval preflights both queues, sets a private approved flag, prepares guest `{seq,type:'join-approved'}` and host `{seq,type:'peer-joined',peer}` before notifying either. Public status remains pending during RTC setup; approved ready changes it to active through the existing heartbeat transition. A separate20-second negotiation deadline begins at approval. Neither endpoint is native gameplay admission.

Before approval, both directions of SDP/ICE and guest ready reject403 `approval_required`. Decline returns guest participant left status without token. Terminal guest `participant-left` reasons: `join_declined`, `approval_timeout`, `reservation_timeout`, `code_replaced`, `joining_locked`. Host `peer-left` closes corresponding request rows. Repeated/cross-room/host/missing resolved approval IDs reject409 `request_unavailable`. Existing errors remain `{error:{code,message}}`.

Rotation/lock cancel only unapproved requests and preserve approved pending/active guests, bearer credentials, seed, host ID, session ID and absolute expiry. Multi-request cancellation preflights every host notice before any code/policy/participant mutation, prepares all terminal guest queues and host notices, then emits once. Failed queue admission, collision retries or code quota preserves the prior room. It does not call ordinary `#leave` during these batches, preventing saturated membership removal from ending unrelated approved guests.

Current/retired code reservations are bounded64 per room (initial included), at most4,096 with the existing64-room quota. Retired codes reject410 `stale_invite`; they cannot resolve or be reallocated until their original room record is removed after end plus60-second retention. Current code remains valid while its room is live. There is no independent invite timer: host departure/timeout, stop, restart or absolute one-hour room expiry ends code validity. Rotation never extends the unchanged room expiry. End/timeout/shutdown/restart invalidates old rooms/codes. Invalid/unknown code401 `invalid_invite`; locked409 `joining_locked`; existing total capacity includes host and pending requests, maximum eight.
