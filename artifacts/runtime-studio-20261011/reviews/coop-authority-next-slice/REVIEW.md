Inputs have no authenticated peer envelope. Host-authoritative snapshots can keep RNG/AI/collision on the host; guests need interpolation and fresh input sequence checks, not lockstep or host RNG replay. Two proposed worker assertions need refinement: rejected `interact_site` calls may legitimately record a newly visited discovery before returning an incomplete-mission error; do not require revision to remain unchanged for that whole call. `Game::new` intentionally drops carried material cargo and can advance retained courier delivery at Haven, so exact whole-profile reload equality is not the existing contract for every profile.

## Recommended next bounded Rust slice

Implement **host-owned eight-peer simulation state and attributable real shots**, before network replication/reward sharing. Keep the existing one-player API as a host-slot wrapper and preserve its behavior. A new `game_core::coop` module can hold bounded admitted peer metadata and runtime state; shared `lib.rs` hooks must explicitly refactor the real control/fire/hurt/collision paths rather than create an unused second player scaffold.

1. Issue a stable session-local `PeerId` after host admission, map it privately to an Entity and a sanitized craft/profile context, and never accept sender/role from `InputFrame`. Limit active peers to8 including host. Keep each peer's body, course/throttle, shot count/cooldown, shield/damage grace, regeneration, nova/wake state and run/cargo context separate. Guest signaling `ready` alone must not grant admission.
2. Add a typed damage source for admitted peer/hostile/environment. Attach peer ownership to primary, Pulse Lens, Echo, guided/royal signatures, reflected bullets, wake and nova. Keep `Segment.owner` as its existing head link. Route real damage through the struck player's vitals/body and identify the actual credited attacker without changing friendly-fire policy silently.
3. Define host tick/snapshot sequence and bounded fresh-input admission (finite coordinates, valid peer binding, stale/duplicate rejection, input timeout releases fire/thrust/course). Do not introduce guest replay. Tick the host world once per1/60 step; never once per participant. Enemy targeting, streamed chunk interest and shared bullet-cap admission must be explicitly deterministic/bounded with multiple players, rather than continuing to use only the host's position accidentally.
4. Keep each local saved Profile/seed immutable under join/session world-seed negotiation. A transient authoritative world seed must be separate from profile.seed before using seeded regions/chunks/campaign nodes. Start with no new shared reward policy: preserve tested solo rewards and make pending attribution policy explicit for co-op. Next transaction slice can define verified per-peer reward receipts, once-only pickup consumption, boss queue ownership and save checkpoints; guests must never submit raw reward deltas or a replacement host Profile. Unattributed remote effects must not fall through into the old singleton host reward ledger.
5. Host end/timeout/replacement invalidates peer input bindings and transport queues; guests disconnect to their own local session/profile with the established carried-cargo abandonment policy. No host migration or silent new host election is in this slice. Explicit leave/checkpoint acknowledgement is needed for clean exit; abrupt process loss cannot promise that unsaved mutations were durable.

Likely affected files: new `crates/game_core/src/coop.rs` and focused actual runtime tests; narrow real `lib.rs` player/tick/control/fire/collision/spawn hooks; `campaign_runtime.rs` guided/signature/heal and reward routing; biome/boss targeting adapters only where a chosen peer target enters the existing controllers. Browser/Rust snapshot and WebRTC DataChannel adapters are a subsequent Root-owned integration seam, not functionality in the signaling service.

## Meaningful first acceptance cases

- Actual native Game step admits host+7 and refuses9th atomically; forged/stale/disconnected peer IDs cannot control another body. Eight inputs advance time/enemy AI only once, not8times.
- Two distinct equipped craft fixtures steer/fire independently; primary fifth/eighth counters and wake/nova cooldowns remain separate. Real body hits/empty-body death damage only the intended peer and preserve occupied-cell/collision-transform parity.
- Real primary/guided/reflected/wake/nova damage carries correct stable owner through enemy segment/head destruction. Simultaneous last hits and a shared projectile cap have an explicit once-only deterministic result; no profile changes from unadmitted signals.
- Two profiles with different seed/XP/currency/cargo survive admission, rejected input and host departure under the declared cargo policy; guest metadata cannot overwrite host profile or saved seed. Checkpoints are compared at actual acceptance/commit boundaries, allowing legitimate migration/cargo-loss revisions.
- Snapshot IDs do not alias after despawn/rejoin, packet counts/size and input queues are bounded, host loss releases held controls. Later browser/RTC/TURN/multi-client gameplay acceptance remains Pending.

This recommendation is source design evidence only; none of these new runtime cases has been implemented or executed here.
