# Fractional source timing on the existing music clock

This is a work-only prototype pinned to Root commit `940836824af19a901097aa072a8a0c11774b4482`. The actual source names are `MusicClock` and `AudioEngine.clock`; there is no new clock or audio player. The copied `inputs/apps/game/src/music-clock.ts` is byte-for-byte that commit's Git blob. Its public beat/time API is both the prototype's structural clock type and the actual implementation exercised by the tests.

The reference duration supplied for this increment is 42.68 seconds, with the provisional 169.275 BPM mapping. Their product is **120.41095 beats**. This period remains fractional. This is timing arithmetic from the supplied reference measurements, not another audio analysis, an accepted tempo transcription, or perceived song-match proof.

## Input and output

`new FractionalEventScheduler(loopBeats, events)` validates, copies, freezes and sorts once. Each generic event has `onsetBeat`, `endBeat` and an opaque `payload`. The first two fields come independently from `referenceBeat(sourceSeconds, 169.275)` for this pinned source mapping. Retain those original absolute measured onsets and ends if a later tempo estimate or playback target changes; that does not silently recompile the timing bank. No integer step, quarter-beat rounding, duration multiplier or source melody is inserted by this primitive. An onset must be in `[0, loopBeats)`; a finite end must be later than its onset and may extend beyond the loop. Notes crossing the source end retain their gate into the next loop. Source score preparation must explicitly decide whether such gates are authored and how a source-end cutoff is handled.

`drain(clock, {fromTime, untilTime, maxWindows, maxEvents})` returns sorted occurrences. Each occurrence carries its original `eventIndex`, `loop`, global `windowStep`, absolute onset/end beats and mapped onset/end times. `(loop, eventIndex)` identifies an occurrence even when multiple input events share one onset. Payload content and synthesis are caller-owned.

Quarter windows remain the existing transport's `[step / 4, (step + 1) / 4)` windows. Within a window, onsets keep their original fractional beats. Both absolute ends and onsets use the real `clock.timeAtBeat`, so a gate crossing a hold, ramp or ramp end follows the transport's integrated timing. It must not be shortened by scaling its beat duration with the onset tempo alone.

`untilTime` is a strict exclusive onset horizon. An end can be later than this horizon. `fromTime` is an inclusive eligibility floor. The actual mapped onset, rather than only the clock's approximate inverse, determines membership; tests cover exact floor/horizon comparisons one floating-point ULP apart. A partially read quarter remains resumable. Repeated or overlapping drains do not duplicate an occurrence unless the caller explicitly resets the cursor.

## Bounds, stalls and capacity

The prototype accepts at most 4,096 static input events, 16 windows and 128 returned events per drain, with a finite horizon of at most 0.5 seconds. Production currently uses `SCORE_LOOKAHEAD_SECONDS = 0.18` and `SCORE_MAX_STEPS_PER_TICK = 16`. The caller must supply that actual production horizon and maintain its own per-tick call bound. The prototype creates no nodes, timers, queues of voices or second beat transport. Those numeric event/window caps do not establish AudioEngine's actual 32 music / 16 SFX voice-budget acceptance, carrier count, node cleanup, DSP cost, or listening acceptance.

The result distinguishes `horizon`, `event-cap` and `window-cap`. A capacity result retains the next occurrence, including the remainder of a simultaneous chord. It never advances past a note merely to fit the cap. Root must inspect the actual reviewed score's worst density and total active gates before integration. Lower synthesis/cosmetic complexity and group compatible notes inside bounded voices before changing source composition. If a caller defers capacity and subsequently stalls beyond those onsets, the next drain reports that explicit loss through `skippedPast`; it does not retroactively claim the earlier cap scheduled everything.

Returned occurrences are consumed by this cursor immediately; there is no second engine-admission acknowledgment API. The caller must have an actual admission policy for every returned event. A later `createVoice()` rejection is not handled by this prototype. Root must coordinate the requested event cap with the active voice budget and overlapping SFX/world/title layers, or explicitly report and handle any such rejection. The prototype's retained remainder at its own capacity boundary is distinct from successful WebAudio voice admission.

A stall seeks directly to the first eligible occurrence and the current **floor** quarter, without walking every missed loop/window or discarding the still-future fraction of that quarter. `skippedPast` counts occurrences before the supplied eligibility floor. If the caller supplies `now + lead`, this includes that lead gap; it is not a count of only physically elapsed AudioContext onsets. The caller chooses and records that policy. No stale notes receive fabricated immediate playback. Empty scores still honor the window cap.

## Tempo invalidation and suspension

`resetAtBeat(beat)` intentionally rewinds/seeks the cursor. Before calling it, Root must cancel every previously scheduled occurrence whose onset is at or after that beat. A retarget preserves heard voices and the shared clock's boundary phase, then resets only cancelled future scheduling to the same absolute boundary. This prototype neither cancels nodes nor retimes an already audible envelope. Returned `onsetTime` and `endTime` are immutable scheduling snapshots, not automatically changing clock bindings. Active voice end-stop/gate automation must independently recompute `clock.timeAtBeat(voice.endBeat)` under every tempo change, including for a stationary long note without new note onsets. The tests exercise title → Haven 120 → combat 166 cancellation and a stored long-note end-beat contract. The existing pad-gate path is one current example, not validation of arbitrary source voice envelopes.

On suspension, the caller clears/releases its owned scheduled audio, preserves the shared transport's frozen beat, and uses the existing `clock.reanchor` on resume. Reset to that frozen beat, preserving loop phase. The new title timing must not reset to loop zero on Continue, corporation blend, combat or release. The source harmonic bank and percussion must share this same absolute transport and remain coherent with Root's reviewed transition plan.

The current production `schedule()`/`invalidateFuture()` and `titleStep()` still use their existing quarter-step score. Integration must coordinate this fractional cursor with the **one** outer schedule/invalidation lifecycle. Do not give each audible area/theme another independent title cursor or schedule the source layer once per crossfading world theme. The prototype does not change those files.

## Proof scope

The timing corpus uses generic labels and mathematical event positions. It contains no inferred or invented source pitch, instrument, harmony, percussion or melody. Two ramp tests compare actual mapped times with independently integrated `60 / BPM(beat)` rather than reproducing MusicClock's logarithmic formula. Other tests exercise fractional periods, loop tails, simultaneous onsets, partial horizons, caller caps, a long stall, cancellation/reset and reanchor with the real pinned clock implementation. The five unchanged existing MusicClock tests are also run directly from their pinned snapshot.

These are pure timing and type checks. Root's source score review, production transport integration, actual active voice/carrier bounds, retimed releases, normal build, native OfflineAudioContext output, transitions, mute/suspend/dispose cleanup and human audition remain open. No renderer, listener, normal build or audio render was started in this pass.
