# Actual combined WASM and RTC acceptance plan

This is a proposed next test, not an executed result. Root owns the temporary listener and browser actions. Reuse the existing bounded co-op QA tool so there is one owned listener, not an additional persistent game preview.

The current `scripts/qa/co-op-transport/prepare.mjs` stages only wire, signaling and transport. Its scope explicitly excludes Game authority. `server.mjs` allowlists those files, rejects individual staged files above 100,000 bytes and accepts the existing transport-only report fields. It therefore cannot currently serve the actual WASM binary, complete 154,158-byte native fixture, controller or ports and cannot validate combined gameplay by itself. Extending it requires an explicit file allowlist, pinned normal WASM glue/binary, suitable finite per-file bounds, exact QA origins and a separately identified report scope. Its browser security policy must be tested with the actual WASM module rather than relaxed globally.

Use real visible buttons to create/join, send held controls, end, rejoin and dispose. Two actual `Galaxy.create` instances must each own a native Game and canvas; disclose if they share a WASM module instance. Supply fresh actual licenses or anonymous pristine profiles, with zero XP/currency. Do not use boosted checkpoint fixtures, diagnostic scene rewards or injected successful replica results. Two actual RTCPeerConnections and ordered DataChannels may share the QA page, but that proves local loopback, not separate networks. Keep invitations, bearer credentials, SDP and ICE out of DOM reports and logs.

Only the host's existing native fixed-step accumulator may tick gameplay. Feed both clients' real sampled input through the actual controller/ports, and verify transport-ready differs from native admission and complete replica commit. Capture actual host/guest actor poses and primary shots, natural cell destruction, complete entity/body counts, native acquisition/revision and commit ACK. Observe reuse of unchanged bodies and a changed body with the same occupied count where feasible; an occupancy-count-only cache is insufficient. Keep the last complete guest frame through partial transfer and install the next only on successful native commit.

Check host end, guest leave, failed cleanup retry, rejoin with a new session/epoch, Title and graphics recovery. Compare canonical local Profile digests before and after for both clients; remote host seed stays separate from guest local seed and identity. Verify no progression/rewards/claims/cargo from shared gameplay and no replica autosave. A session cannot be considered restored while native cleanup reports failure. Record actual created/closed PCs, pending requests, timers and surviving native views without publishing capabilities.

Independent durable saves require separate storage origins. `SaveStore` opens the fixed IndexedDB database `galaxy-royale` at version 5, so two stores on the same origin share one database. Two Galaxies in one page can prove separate in-memory Profiles, but cannot honestly prove independent databases. For that scope, use two explicit QA origins/iframes on the same owned listener, each with its actual SaveStore and local database. Exact-origin signaling/CORS and any in-memory capability transfer must be purpose-built and reviewed; secret-free reports may be consolidated. Do not add a production database name override just for the test.

The main hidden-tab policy pauses the host native clock. Verify reset/cancellation and the guest's expected stale timeout separately; do not infer hidden host simulation support. Initial acceptance is bounded local desktop loopback with real native worlds. Eight browser participants, mobile/background behavior, packet throughput/latency, Internet HTTPS deployment, STUN/TURN/NAT traversal, full cosmetics/abilities and durable reward release remain separate work.
