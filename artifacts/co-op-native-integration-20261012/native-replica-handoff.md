## Runtime contract

`game_core::co_op_replica::Replica::new(session: ParticipantId, peer: ParticipantId, epoch: u32, world_seed: u32) -> Result<Self, &'static str>` binds the authenticated signaling metadata at admission. `stage(Header)`, `entities(acquisition, EntityPage)`, `body(acquisition, BodyPage)`, `commit(acquisition, revision)`, `end(session)` return `Result<(), &'static str>`. Root's single-op JSON wrapper maps success to `{v:1,ok:true,value:null}`. Page DTOs remain session/tick/revision tagged; acquisition is a separate operation argument. No Profile, inventory, currency, rewards or authority tick can be supplied.

One pending and one committed scene are retained. Seed/session/local epoch, monotonically accepted acquisition/tick/revision, strict serde fields (including identity), scalar bounds, page order, sorted unique indexes and all aggregate counts are validated. Only a complete acquisition with matching domain-separated FNV-1a64 content signatures can swap presentation. Failures retain the previous committed scene and do not acknowledge a new commit. Old bodies reuse Rc only when ID/signature/dimensions/occupied count all match. Same-count topology and RGBA changes require new cells. Zero-occupied bodies import exact dimensions and verify the empty signature without a page. End drops both scenes and permanently invalidates that Replica object.

`Scene` provides immutable header()/entities(), world_seed(), home_corporation(), local_pilot(peer), focus(peer,alpha), blend_seconds(), light_sources(ViewInput), guest_hud(peer,camera,baseHud), and render_into_with_home(frame,ViewInput,callback). `ViewInput` fields are camera/viewport Vec2 in world units, alpha0..1, reduced and reduced_motion. Invalid view input leaves the caller's FrameBuilder intact. Valid render clears it and composes host-seeded cosmic/regional backgrounds, canonical site/standard champion scenery, home dock callback/fallback, safe ring/facilities/crest, occupied bodies and primary-shot trails. It does not create a second Game, tick physics or write a Profile.

Whole occupied cells use exact imported RGBA including alpha-zero occupancy and holes, actor rotation heading+PI/2 (matching current actual Game actor_transform), interpolated pose and original scalar size with no arbitrary cell-size floor. Culling includes actual body canvas bounds plus published radius. Poses interpolate between completed captures with stable IDs and participant epoch guards; at most512 body poses and180 shot poses. blend_seconds is actual tick gap clamped1/60..0.1s; first capture uses native previous60Hz pose, never extrapolation. Header and gameplay state remain untouched. Root tracks time since successful commit and supplies alpha; this is not a60Hz network-rate claim.

Factory guest Hud derives temporary factory Profile/Stats through the exact existing guest_profile helper, without a second Game or saved-profile mutation. It uses authoritative position/vitals and host seed/biome. Local XP, currency, kills, cargo/stash/components, quest/discovery/patch/ship collections, purchase/action flags, loss/run history, boss counters and onboarding are cleared; only factory ship/loadout metadata remains. This helper rejects host or nonfactory guest requests rather than guessing owned host stats. Lights are bounded to two actual retained projectiles plus visible home beacon; no local solo transient lights leak.

## Bounds and honest limits

Existing publication caps remain512 entities, dimensions512x512,1,048,576 aggregate storage cells,8 pilots,180 shots,64 entity rows/page and1024 cells/page. Body staging reserves exactly admitted occupied count; maximum staged cell payload8MiB. One packed body set is at most4MiB RGBA +128KiB occupancy plus less than4KiB per-body bitset rounding, excluding allocator/metadata overhead; old/new cache sets can overlap while committing, and pending cells remain until swap. Original Game/renderer/wire buffers and cold scenery initialization are separate. No CPU percentile/GPU/RSS/device performance claim.

Current publication does not encode active boss rig/IK phase, family/generation/parent links, loot/particles/wake, recent damage timestamps or hit/exhaust lights. Guest uses actual received occupied bodies/poses and basic shot presentation; full advanced visual parity is pending. Mission claimed/ready/tournament progression is not inferred. Scenery uses captured tick/60 rather than predicting host cosmetic time. Factory guest owned-hull/loadout validation, abilities beyond the primary-fire authority slice and shared rewards remain unfinished. Native transaction tests are not browser/NAT/separate-device acceptance.
