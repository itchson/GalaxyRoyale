The actual pending request field is `JoinRequest.id`; approval and decline resolve the one current request rather than guessing a peer index. Host rotation and lock use existing controller methods. Raw invite grants remain private command replies; public observations and strict server reports exclude room codes, participant/session identifiers, tokens and private room facts. Pending-only gates reject new PCs, native admission or commits. Decline and policy cancellation require exact expected terminal reasons and bounded resource cleanup. Replacement first verifies approved continuity, retires the approved guest, then attempts the old code and requires `stale_invite`; fresh pending replacement requires `code_replaced`. The baseline transport's complete policy tuple, request birth revision and strict event handling remain intact; this parent tests sequential policies, not every overlapping race.

There is one host create per case. One attempted-case latch, finite native lifetime preflight, 120-second action deadline, bounded reply waits and separate 20-second cleanup bound prevent unbounded retry. Timeout replies cannot qualify late. Cleanup actually asks both children to leave, verifies solo/PC/request/timer retirement and normalized Profile/persisted equality, and retains a preceding failure even if cleanup also fails. Later disposal remains required by the operator.
