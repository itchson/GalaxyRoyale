## Concrete two-client rounds

**Decline round:** start two paused native clients and create one host room. Record private room/native/counter marks. Guest joins; wait for host pending1 + guest awaiting with no new PCs/ready/admission/replica begin. Decline the exact current request before its real 20-second window expires. Require guest actual `join_declined`, ended/solo, pending cleared, no new PCs/native guest admission, unchanged normalized native/persisted digests, and guest requests/timers zero. Host stays in the same room/seed/host identity, hosting, without native end/begin. Do not require host timers zero while it is hosting. A fresh request ID is needed for a new join.

**Replacement round:** first use the normal actual Accept/owned-commit chain. Mark room/host/seed, guest epoch, cumulative PCs/native ownership and commit count. Rotate with the approved guest connected; require code changed/revision increased, same room/host/seed/epoch, unchanged PC/native ownership counts and additional real guest commits. Only then guest leaves and restores solo. Joining the old private code now must produce actual `stale_invite` with no new PCs/admission or profile change. Join the current code and hold pending, rotate again, then require actual `code_replaced`, cleared pending, solo guest cleanup and continuing same host room. Do not use `join(oldCode)` on the still-connected guest to test continuity: join intentionally retires that guest session.

**Lock round:** start pending; set lock true and require actual guest `joining_locked`, zero PC/admission delta, solo cleanup and retained host room. A new attempt while locked must report actual `joining_locked` before any pending/PC/native guest ownership. Unlock; require lock false and increased revision while room/host/seed remain equal. Create a fresh pending request, accept normally, and confirm new complete owned commits. Optionally lock/unlock while this approved guest remains connected and require the same continuity mark plus new commits. With two clients, approved-preservation and pending-cancellation are separate phases; simultaneous proof needs a third real game client.

End hosting after each round, check both solo modes, all created PCs closed and requests/timers zero, verify unchanged digest observations, then dispose. Do not clear/rewrite/import profiles or alter seeds. `SaveStore.open` can migrate records: the current helper is not a zero-write legacy-save gate, and normalized digest equality does not prove exact boxed ECS/RNG/body/presentation preservation. Native restoration proof remains separately owned by the engine counterpart.
