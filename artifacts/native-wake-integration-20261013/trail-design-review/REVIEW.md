## Original findings, resolved by the pinned version-two addendum

1. **Make f32 lifetime validation identical.** `Math.fround(3.4)` is the correct upper bound, but a raw-JS-positive/raw-upper comparison still differs from a derived native f32 parser plus bounds check. The independently recorded IEEE-754 conversion model confirms `1e-46` becomes f32 zero (raw JS positivity accepts it), and `3.4000001` rounds to `3.4000000953674316` (a native f32 upper check accepts it while raw JS upper comparison rejects it). This is a mathematical model and primary-source review, not a executed future validator. Choose and document either post-f32 semantics on both sides, or raw-f64 bounds plus representable-positive conversion on both. Include actual co_op_batch Value/replica wrapper fixtures for zero, underflow, first subnormal, exact upper, just-over upper rounding, next f32 and ordinary published native life. Coordinates require the same documented conversion convention; do not accidentally broaden existing protocol without a reason.

2. **Fence same-tick removed-key reappearance.** The initial proposal retains expired records which remain in the full list, correctly preventing same-tick deadline renewal for those keys. Its step 2 removes missing records. Therefore complete populated tick T -> complete empty/legacy tick T -> complete positive same key tick T can currently treat the removed key as newly observed and create a fresh deadline. That violates the advertised no same-tick resurrection guarantee. It is not a reproduced runtime defect because there is no implementation yet. Resolve by rejecting immutable same-tick set mutation for unchanged membership, or retaining a bounded current-tick seen-key fence after visual deletion. A maximum 192-key, current-tick fence is sufficient; it need not be an unbounded tombstone journal. Strictly newer committed ticks may still revalidate real still-active state after host simulation pause, as the design explains.

3. **Include the native anchor halo in this new position bound.** `co_op.rs:836` confines pilot position/previous position to +/-WORLD_LIMIT, but `co_op_wake.rs:32` places the sample at the pre-integration origin minus 14 forward. The actual legal source can therefore stamp x=1,000,014 from an inward-facing pilot at x=1,000,000. The proposed +/-1,000,000 page position validator would reject that native point. Define a cosmetic point bound WORLD_LIMIT+14 (with matching raw/f32 checks) or a reviewed explicit cosmetic omission; never clamp or alter the authoritative wake sample merely to satisfy serialization. This is source-derived compatibility reasoning, not an executed edge fixture or runtime reproducer. Future actual native edge-capture tests should exercise heading on each boundary while the existing pilot/projectile schema bounds stay unchanged.

## Source-supported gates for the future implementation

- Capture at most one actual birth per slot/authoritative tick; tick overflow is already checked in real tick_co_op. Store born_tick with the authoritative sample rather than a parallel generator. Match page session/tick/revision and participant slot -> ID/epoch from the pending header. Order slot then birth, <=24/member and <=192 total. Empty/omitted metadata means clear on complete commit; null/unknown/duplicate/future/mixed-epoch fields reject.
- Require every advertised positive-state page before commit and reject unexpected/duplicate pages. Build/validate cross-cache stationary-position and lifecycle reconciliation before taking/mutating the visible Scene's existing caches. Existing commit only moves the Nova cache after all body/identity/signature checks. A future wake validation error after that move would violate atomicity.
- Monotonic clock validation happens before mutable bridge execution. Normal clock advancement may expire already committed visuals while a pending transfer fails; this is presentation time, not pending data admission. Invalid/regressing/nonfinite clock must mutate nothing. Never use pose age, capped frame dt or alpha as wake lifetime. Same-tick checks must compare to the last committed scene, not a merely staged/failing header watermark.
- A first populated commit renders current positive-life state; do not reuse Nova's first-journal baseline skip. Header-to-commit delay is subtracted so slow assembly expires samples honestly. Network time before header receipt remains unknown. Newer-tick revalidation of a host-paused still-damaging sample is justified; local presentation expiry is not native gameplay death. No birth sound/particles/light/damage replay accompanies a restored live dot.
- The dedicated page avoids multiplying 192 points into the combined 180-shot/32-Nova/eight-loadout header. Enforce actual serialized payload <=32768 bytes and exact transport/native wrappers <=65536. The existing max-density owner-null-shot header is only a measured fixture, not the supremum of every valid field encoding. Require new actual native/Value/browser fixtures with owner-bearing shots and long float forms.
- Current controller distinguishes entity vs packed-body pages through an entities-array branch and otherwise accesses cells; wasm-ports similarly routes any non-entity page to replica_body. Both need explicit strict points-variant handling. Body-signature cache omission is exclusively for cells, never the wake page. Header/body_pages retain their geometry meaning; track one separate required wake page and do not change occupied/storage/signature totals.
- Existing capture holds until all admitted peers acknowledge, generates <=4 pages/frame, sends <=2 pieces/peer/frame, caps each peer at 1 MiB and 80 frames per second, and uses 30-second transfer expiry. The proposal accurately treats these as ceilings; it cannot guarantee 20 Hz. A warmed 120-row capture with no changed cells plus wake is five frames (<=16 publications/sec by frame budget); a 512-row capture is eleven (<=7.27/sec). Actual serialization/backpressure and initial-body latency may be slower. Test fast cached emission and delayed complete omission; do not extend TTL to conceal transfer delay.
- Shared append must preserve solo five quads, 2-unit size, radius-6 spacing, source color/alpha saturation and pre-actor order. At 192 points it admits <=960 quads, independent of the existing particle-entry pool. Reduced motion freezes phase but not expiry. Exact controlled-phase/native geometry tests do not prove normal-network phase/TTL parity or GPU appearance.
- Leaving guest/death/reset sample ownership and epoch rules remain native. On guest end dispose presentation state. Existing birth lights have a separate shared 32-source admission/eviction history; a live sample does not prove a native light survived. The first increment correctly adds no guessed light or audio. The optional tagged-light amendment is separate and needs exact combined pool/visibility/cleanup tests, not 192 inferred lights.

No runtime approval is recorded in this review. The three refinements are resolved by the verified addendum; later implementation needs native/strict boundary/slow-transfer tests and actual guest captures before practical visual/RTC claims. Native damage, Profile/save behavior, Root live room evidence and prior boxed-world/shadow gates remain independent.
