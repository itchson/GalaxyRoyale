## Integration findings

The six menu pages have actual tab controls, `role=tabpanel`, exclusive `hidden` state, selected state, and roving keyboard tab indices. Left/Right/Home/End select and focus the same page controls. Before-launch settings returns to the title; flight settings, journal, upgrades, hangar, champions and backups are distinct page bodies. Purchase/craft/select/challenge/quest actions call the existing real Rust APIs and persist their resulting profile. Menu navigation itself does not grant points, XP, ownership, patches or completed missions.

Pause disables/resets held input and clears the adapter's pending course. Console/dialogue opens suspend flight; their close callbacks restore flight only when prior state and all modal/background/recovery checks permit it. `resume` checks console/dialogue/visibility/recovery before flight and again after awaited audio resume. Encounter preparation uses an epoch and durable save/flush before closing its modal and resuming. Return-to-title invokes the existing real retreat/banking path, clears input/modals and remains paused at Haven. Visibility changes pause/save; foreground return does not silently consume paused gameplay time. Source review of these guards is not a new real-browser race replay.

The semantic bridge maps measured DOM bounds to logical group coordinates. It intersects panel and actual scroll clips on both axes, filters hidden/off-clip controls, caps nodes/text, and passes selected/disabled/action-color state separately from hover. Authoritative `data-active`/`aria-selected` changes invalidate the scene. The authored campaign icon normalization remains limited to 1/64 logical unit around 24/32-cell bounds. Native clipping is cell-center based; it is not a GPU scissor guarantee for every fractional edge. Menu panels/font/icons use unlit materials.

Final Browser calls `draw_ui_with_boss_panel_and_touch` with the actual touch state and inset logical viewport. The painter and boss reservations share `FlightLayout` and the same touch rectangles; safe-area offsets are added once. Normal 533×300 layout retains its original panel geometry. Narrow layouts omit optional currency/radar before hull/shield, use compact bounded captions, and put the micro meter above controls below width290. World projection uses eased zoom extent; UI projection stays logical zoom one. None of those presentation decisions modifies hull, currency, ship rank, controller force or collision state.

The final tiny-input addendum supersedes only the old two-pixel touch overlap: safe widths180/181/182 now use joystick widths82/83/84, with centers55/55.5/56 and unchanged fire rectangle. The CSS's `min(84*scale,100vw-safeLeft-safeRight-98*scale)` and native formula agree.
